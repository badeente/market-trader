## Frozen first recipe

- Input: exactly eight contiguous completed DEUIDXEUR m15 candles (preserving the existing source's literal instrument token `deuidxeur`, without case normalization) ending at the historical decision time; UTC, same instrument/interval, all close_time and available_at <= decision_at. Strict OHLC positivity/ordering/finite Decimal validation. Before fixed-point expansion/Fraction arithmetic, reject coefficient digits, absolute exponent or expanded integer digits above1000; these resource limits are part of the recipe. Builder applies the same limits to all source/history/future OHLC and also enforces the same eligible research session.
- Image: 256x192 RGB PNG, only candles, no volume/indicators/axes/text/timestamps/targets/results/labels. Background RGB(17,24,39), up(46,204,113), down(239,83,80), doji(200,200,200). Fixed12px margins, fixed12px body width,1px wick, equally spaced x-centres, minimum1px body height. Integer pixel coordinates and rational/fixed-context arithmetic, no font/antialias dependency.
- Y-scale from ONLY the eight input lows/highs, padding5% of their range on both sides. Flat window padding0.001 on both sides. No global/source/future extrema or fit statistics. Price mapping uses exact rational arithmetic, deterministic integer rounding declared in recipe.
- Encoding: no optional image libraries. Standard-library PNG, fixed zero-filter scanlines and stored DEFLATE blocks for stable output, onlyIHDR/IDAT/IEND, no metadata chunks. Validate via independent decoder/browser. Primary PNG reference: W3C https://www.w3.org/TR/png/ (baseline RGB8/noninterlaced only, not exotic features).
- Recipe includes format/version, all geometry/colors/scale/encoding rules and renderer implementation SHA256. Recipe_id is SHA256 canonical recipe bytes. Changing renderer bytes/policy invalidates cache conservatively. Input image identity uses recipe+only consumed candle OHLC/time/instrument/interval/availability, excluding volume/labels/target/future/global dataset IDs. Same causal input and recipe => same image key/PNG bytes even when targets or future prices differ.

## Ownership/API

Renderer owner: NEW `src/market_trader/chart_images.py`, `tests/test_chart_images.py` only.
- `chart_recipe()->dict` (complete recipe incl recipe_id), `render_candles(candles:tuple[Candle,...], *, decision_at:datetime)->bytes`, `image_key(candles, *, decision_at)->str` returns `sha256:<64hex>`.
- `window_payload(candles, *, decision_at)->dict` returns canonical consumed input metadata (no volume/labels) after strict validation; used by builder samples. Must not import trainers/Torch/NumPy. No changes to domain/data.

Bundle owner: NEW `src/market_trader/image_dataset.py`, `tests/test_image_dataset.py` only. Renderer API may arrive concurrently; use shared contract, no renderer edits.

- `verify_image_dataset(output:Path)->dict` returns manifest after complete checksum/schema/inventory/identity/row/label/image validation; no arbitrary file references. It must not need source inputs or trainer runtime. For PNG verify supported bytes/hash/recipe consistency; inputmetadata sufficient to regenerate each PNG using current recipe, detecting re-signed wrong images. Source-identity fields are safe identifiers, not absolute paths.
- Samples format `market-trader.image-samples.v1`, top rows `samples`; each row `sample_id,split,decision_at,image_key,image_path,image_sha256,window` (`window` exactly window_payload result), target fields ONLY in labels. `window` shape: instrument, interval_microseconds, decision_at, candles (8 dictionaries with open_time/close_time/available_at and open/high/low/close string prices). Manifest includes `recipe_id`, source dataset/training identities, fixed horizon/lookback/time/sampling policy and `artifacts` checksums.
